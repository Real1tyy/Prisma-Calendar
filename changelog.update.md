### Improved
- **Settings explain multi-device use**: a **Using several devices** box under General (next to Read-only mode) and a **Syncing from several devices** box under Integrations describe what Prisma writes on its own, what to sync, and the situations that still call for a single writing device — auto-assigned ZettelIDs, external calendar sync, reminders and the time tracker. The Read-only mode description lists everything it turns off. See [Multiple devices and sync → What to be aware of](./features/advanced/multi-device-sync.md#what-to-be-aware-of).

### Fixed
- **One calendar across all your devices**: with the vault synced (LiveSync, Obsidian Sync, iCloud, Syncthing, git), every device now makes the same automatic decisions, so Prisma's own housekeeping no longer produces duplicate notes or sync conflicts. A recurring series gets its id from its source note, so two devices that both index a new series before the other's write arrives agree on one id instead of each generating a full second set of instances; an id that a sync conflict changed on disk is adopted rather than fought over. A recurring instance whose file arrives from another device just as it is being generated is used as-is instead of being created again with a ` 1` suffix. And when two notes do end up holding the same recurring instance or the same synced CalDAV/ICS event, every device keeps the same one — the canonical name — instead of each device trashing the other's copy. An all-day event's **Sort Date** is now the same on every device regardless of timezone. See [Multiple devices and sync](./features/advanced/multi-device-sync.md).
- **Quieter housekeeping, and read-only mode that means it**: every automatic write Prisma makes — marking events done, **Sort Date**, **Calendar Title**, reminder flags, recurring-instance updates, series propagation, the time tracker's periodic end-time save, CalDAV/ICS updates — now waits until the vault is indexed, runs one write at a time per note, and is skipped entirely when the note already holds the value, so a note that another device already updated is not rewritten just to end up identical (fewer sync events, no phantom conflicts). A write queued for a note that gets renamed in the meantime follows the note instead of being lost. **Read-only mode** now covers all of these too: a read-only device does not sync external calendars, normalise **Sort Date**, save time-tracker progress or propagate series changes. See [Multiple devices and sync](./features/advanced/multi-device-sync.md#limiting-writes-to-one-device).
- **CalDAV and ICS subscriptions keep every note in step**: a note synced under an account or subscription that no longer exists on this device (settings not synced yet, or the account re-added) is adopted by the current one instead of being ignored forever — it updates and deletes again like any other synced note. A server-side change that only touches the event's version tag is now written to the note too, so a sync no longer re-plans the same update on every start. Synced notes no longer record the moment this device synced them (`lastSyncedAt`) — the one value two devices could never agree on; a note written earlier keeps it until its next update, which drops it. See [Integrations → Syncing and vault indexing](./features/advanced/integrations.md#syncing-and-vault-indexing).
- **All-day events are marked done after their day ends**: the periodic scan marked an all-day event done at midnight at the start of its day; it now waits until the day is over, the same as when the note is indexed. See [Recurring Events → Generation Control](./features/events/recurring-dsl.md#generation-control).
