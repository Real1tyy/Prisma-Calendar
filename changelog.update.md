### Added

- **Multi-day all-day events with `Start Day` and `End Day`**: Represent a vacation or conference with one note, choose its first and last days in the form, and move or resize its calendar bar with undo across calendar views. All-day events now pair `Start Day` with `End Day`, matching the timed `Start Date` / `End Date`; a single-day event needs only `Start Day`, and `End Day` is written only when an event spans several days. File-menu editing and previews retain the inclusive range; ICS import/export, URL subscriptions and CalDAV preserve the whole span, and a single-day event is exported without an end — so a multi-day event imported from another calendar now covers every one of its days instead of only the first. Thanks to [@MarcoDeco](https://github.com/MarcoDeco) for the [idea](https://github.com/Real1tyy/Prisma-Calendar/issues/60), [@talacada](https://github.com/talacada) for backing it, and [@Photon89](https://github.com/Photon89) for [reporting](https://github.com/Real1tyy/Prisma-Calendar/issues/85) the import collapsing to one day. See [Start Day and End Day](./configuration/properties.md#start-day-and-end-day).

### Improved

- **`Start Day` is the new default for all-day events — migration guide**: New calendars use `Start Day` instead of `Date` for the first day of all-day events, and the setting is now called **Start day property**. Your existing calendars keep `Date` automatically and everything works as before — no note is rewritten and nothing needs to change. For consistency and readability I recommend switching anyway: rename `Date` to `Start Day` across your notes (right-click `Date` in Obsidian's **All properties** view → **Rename**), then set **Start day property** to `Start Day` in each calendar's Properties settings, and update any Bases or Dataview queries that read `Date`. Scripts using the settings API read and write `startDayProp` instead of `dateProp`. See [Using Start Day instead of Date](./configuration/properties.md#using-start-day-instead-of-date).
