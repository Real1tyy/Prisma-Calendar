### Added

- **Collapsible calendar header on mobile**: on a phone — or any pane under 768px — the calendar opens with its header collapsed to a **▾** beside the capacity figure in the view header, so the grid starts right below instead of under five rows of chrome. Tapping it opens two rows: the arrows, **Create**, **Filters**, **Tabs** and **Nav** on the first; the untracked-events menu, **Events**, **Batch**, the all-day control and **Views** on the second. **Tabs**, **Nav** and **Views** each reveal one more row — the view tabs; **Today**, **Now** and the date (shortened to fit, like **Nov 4**); and the **year / month / week / day / list** switcher — and all start hidden, so anything you don't need costs no space. **N filtered** and **N skipped** fold into one eye icon that opens a menu of both and only appears when something is hidden. In batch selection the untracked-events menu steps aside and **Exit** sits next to the date. **Batch Select** reads **Batch** at this width, and a row that can't fit continues on the next line instead of cutting a button off. Nothing changes on desktop. See [Calendar View → Mobile layout](./features/calendar/calendar-view.md#mobile-layout).
- **All-day display modes**: a new **All-day** button in week and day views cycles the all-day strip through four states — the usual capped strip with its **+N more** link, a full-height strip showing every all-day event with nothing hidden or clipped, all-day events only with the timed grid hidden, and no strip at all so the timed grid takes the whole height. The label tells you which one you're in, and the choice lasts until you close the view. Month, year, and list views keep their own **+N more** behavior. Works on mobile and desktop. See [Calendar View → All-Day Display Modes](./features/calendar/calendar-view.md#all-day-display-modes).

### Improved

- **Phone layout, everywhere**: the view tab bar now takes a single row at every width, filling it with every tab that fits — a tab too wide is skipped so a narrower one after it still gets the space — and listing the rest behind **⋯** (Dashboard sub-views included); the tab you're on always stays visible. On a phone, the view header shows the capacity figure instead of the calendar's name when capacity tracking is on; the untracked-events menu opens as a full-height panel centred on the screen instead of half off its left edge; search boxes on phones and tablets no longer open the keyboard the moment a menu or dialog opens (creating an event still puts the cursor in its title); and the **Events** dialog fits the screen, with sideways-scrolling tabs, a type filter that stays inside its box, and each event as a card with its buttons underneath. See [Calendar View → Mobile layout](./features/calendar/calendar-view.md#mobile-layout).

### Fixed

- **Mobile events per day: 0 now means unlimited**: setting **Mobile events per day** to 0 did not lift the cap on phones, even though the setting says 0 is unlimited. It now behaves like **Desktop events per day**. See [Calendar UI](./configuration/calendar-ui.md).
